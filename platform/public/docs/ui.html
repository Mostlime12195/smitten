UI

UI pieces draw on top of the game, in screen pixels, and the camera doesn't move them, which suits scores, health bars and menus.
To showLabel (text), Bar (health, progress), Panel (a box behind other UI), Picture
To workButton, Slider, Checkbox (a tick box, a switch, or one of a choice), TextInput (a box to type in)
To lay outRow, Column, Grid, Scroll (a list longer than the screen)
For touch screensTouchStick and TouchButton (Input: Touch)

They are building blocks: a settings screen, an inventory or a chat box is some of these put together (below is one). A UI piece inside another is laid out inside it.

#Layout

Each UI piece is placed from an anchor: a corner, an edge, the center, or fill (the whole screen, or the whole of the UI piece it's inside). x and y are the distance in from that anchor. With the anchor bottomRight and x, y at 16, a piece sits 16 pixels in from the bottom-right corner on any screen size.

Every setting can change while the game runs:

Message.text = "Level complete!"
tween(Message, 0.3, { opacity = 1 })

getRect() returns where a UI piece is on the screen right now, and visible and opacity hide or fade it along with everything inside it.

#Laying things out

Placing every button of a menu by hand gets old. A Row, a Column or a Grid places the UI pieces directly inside it, in the order they are in the Scene panel:
RowLeft to right
ColumnTop to bottom
GridIn columns, row after row: an inventory, a level select
ScrollTop to bottom (or left to right) in a window that scrolls

Inside one of these, a piece keeps its width and height, and its anchor, x and y aren't used: move it by dragging it up or down in the Scene panel. The container itself is still placed by its own anchor, so a Column with the anchor center is a menu in the middle of any screen.

SettingWhat it does
gapThe room between one piece and the next
paddingThe room between the container's edges and the pieces
alignItemsAcross the way the pieces run: start, center, end, or stretch to make them all as tall as the Row (as wide as the Column)
justifyAlong the way they run, when there's room left: start, center, end, or spaceBetween to spread them from edge to edge
width, height0 fits what's inside. Set one and the container is that big whatever it holds
grow (on a piece inside)Its share of the room left over in a Row or Column: one piece with grow 1 takes it all, two share it

Containers nest: a Column of Rows is a form, with a Label and a Slider in each Row. They draw nothing themselves; put one in a Panel for a background. They work the layout out again only when something inside them changes, so a big menu costs nothing while it sits there.

Pieces made while the game runs line up like the rest:

-- On a Column: one Button for each saved game
function ready()
  for i, name in ipairs(load("saves", {})) do
    local b = self:spawn("Button", { text = name })
    b:on("clicked", function() go("scenes/game.scene", { save = name }) end)
  end
end

#Scroll

A Scroll is a window onto a list longer than itself. It stacks the pieces inside it like a Column, each as wide as the Scroll (with direction set to horizontal: like a Row, each as tall), and shows the part that fits. The mouse wheel scrolls it, and so does a drag or a flick with a finger or the mouse; moving the keyboard focus to a piece out of sight scrolls it into view. For a scrolling grid, put a Grid inside.

List.scrollY = 0                 -- back to the top
List:scrollTo(List.Item20)       -- just far enough to show a piece

#Buttons

When a Button is clicked or tapped, its script's clicked() runs (Pictures and Panels get it too):

-- On a "Play" button
function clicked()
  go("scenes/level1.scene")
end

From another script, listen with Play:on("clicked", function() ... end). pressed("jump") is always the input call, in a Button's script as anywhere else.
disabledCan't be pressed; drawn faded
isHovered(), isDown()The pointer is over it; it's held down
hovered(), unhovered()Events when the pointer arrives and leaves
smitten.mouse.isOverUI()The pointer is over any button or panel

#Sliders

A Slider picks a number between min and max by dragging its knob (or clicking anywhere on its track). step makes it move in jumps: 1 for whole numbers. Its script's changed(value) runs when the player moves it:

-- On a Slider with min 0 and max 1
function changed(value)
  masterVolume(value)
end

Setting value from a script moves the knob without calling changed(). vertical turns it to run bottom to top.

#Checkboxes

A Checkbox is a box to tick with words beside it; with look set to switch it's a switch that slides. toggled(checked) runs when it changes:

function toggled(checked)
  fullscreen(checked)
end

For a choice of one among several (easy, normal, hard), give the Checkboxes the same group name. In a group, ticking one unticks the others inside the same piece, and they are drawn round:

-- On each of three Checkboxes with group "difficulty"
function toggled(checked)
  if checked then game.difficulty = text end
end

#Typing boxes

A TextInput is a box to type in. Click or tap it and type; on a phone the keyboard comes up. It has a caret, a selection (drag, or Shift with the arrow keys), Ctrl+A, copy, cut and paste, Home and End, and Ctrl with the arrows to jump a word.

-- On a TextInput
function submitted(text)       -- Enter
  print("Hello, " .. text)
end
SettingWhat it does
placeholderFaint words while it's empty: "Your name"
maxLengthThe most characters it takes
allownumbers, letters, or only the characters in allowCharacters
secretDots instead of characters
multilineSeveral lines: Enter starts a new one, and Ctrl+Enter submits

changed(text) runs on every edit, submitted(text) on Enter, and focused() and blurred() when typing starts and stops. text is what's in it: read it or set it at any time.

While a TextInput is being typed in, the keys go to it and not to the game: typing "w" doesn't walk, and pressed("jump") doesn't fire on the space bar. Typing ends with Escape, Tab (on to the next piece), a click somewhere else, or blur().

For text input of your own making, without a piece, typed() is what this is built on.

#Skins

Panels, Buttons, TextInputs and Sliders are drawn as plain colored shapes until you give them a skin: a picture to draw instead. A skin is stretched in a way that keeps its corners: skinEdges says how many pixels at each edge stay their own size, and only the middle stretches. One 24 × 24 picture of a wooden frame with skinEdges at 8 makes a panel of any size with crisp corners.
skinThe picture
skinEdges8 for all four edges, or 8, 4, 8, 12: left, top, right, bottom
skinHover, skinDown (Button)Pictures for under the pointer and held down. Without them the skin is drawn a little lighter and darker
knobImage (Slider)A picture for the knob; skin is the track, and color tints the filled part
skin, skinChecked (Checkbox)Pictures for the box, unticked and ticked

In a project whose display is set to pixel, skins aren't smoothed, like every other picture.

#Menus for keyboards and gamepads

Turn on autofocus on a Button (or a Slider, Checkbox or TextInput) and it has the focus when the scene starts. The arrow keys, d-pad and stick then move the focus to the nearest piece in that direction, Tab and Shift+Tab step through them in order, and the focused piece shows a ring:

Focused pieceWhat the keys do
ButtonEnter, Space or gamepad A press it
CheckboxEnter, Space or gamepad A flip it
SliderLeft and right move it (up and down for a vertical one); hold to keep going
TextInputKeys type. Up and down leave it for the piece that way, Tab goes to the next, Escape or gamepad B ends the typing

Clicking a piece also focuses it, and focus() moves the focus from a script. While nothing has focus, the arrow keys go to the game as usual.

Any player's keys and gamepad work a menu. If a piece, or one it's inside, has a player (More than one player), only that player's input does: a menu each for split screen.

UI keeps working while the game is paused, which is what pause menus need (Pausing).

#A settings screen from these parts

Nothing here is a ready-made options menu; this one is built from the pieces above, and yours can be shaped however your game needs.

Panel      Settings    anchor center, 360 × 250
└ Column   Menu        anchor fill, x 16, y 16, gap 12
  ├ Label    Title       text "Settings"
  ├ Row      VolumeRow
  │ ├ Label    (text "Volume", width 100)
  │ └ Slider   Volume    min 0, max 1, grow 1
  ├ Checkbox Fullscreen  text "Fullscreen", look switch
  ├ Row      NameRow
  │ ├ Label    (text "Name", width 100)
  │ └ TextInput Name     placeholder "Your name", maxLength 12, grow 1
  └ Button   Back        text "Back", autofocus on

The Column stretches each row to its own width, and grow gives the Slider and the TextInput whatever the Labels leave. All of that is set in the Inspector. Three short scripts make it work:

-- On the Volume slider
function ready()
  value = load("volume", 1)
  masterVolume(value)
end

function changed(value)
  masterVolume(value)
  save("volume", value)
end
-- On the Fullscreen checkbox
function ready()
  checked = fullscreen()
end

function toggled(checked)
  fullscreen(checked)
end
-- On the Name box
function ready()
  text = load("name", "")
end

function blurred()          -- typing ended: Enter, Escape, Tab or a click away
  save("name", text)
end

function submitted()
  blur()
end

With a gamepad or the arrow keys, the focus starts on Back and moves up through the box, the switch and the slider.

PropertyTypeDefault
anchorenum"topLeft"The point from which the piece measures x and y. fill covers the screen or the parent UI piece. Inside a Row, Column, Grid or Scroll, that piece decides the position.
xnumber (px)0The distance in from the anchor.
ynumber (px)0The distance in from the anchor.
widthnumber (px)160The width. It has no effect when anchor is fill.
heightnumber (px)40The height. It has no effect when anchor is fill.

A Label's words can do everything on the Text page: tags for colors, sizes and effects inside the text (turn on rich), an outline or a shadow, shrinking to fit (fit), typing themselves out (reveal()), and links that call linkPressed(name).

Event (a function in its script)

function eachCharacter(c)The engine calls it for every character each time it draws the text. Use it to move or color the character: c.y = math.sin(c.time * 4 + c.index) * 3. You can change x, y, rotation, scale, color, alpha and visible of c. You can read index, count, char, line, time and since. The engine uses the same table c for every character, so do not keep it.
function linkPressed(name)The engine calls it when the player clicks or taps a [link=name] in the text.

#TouchButton

A button for a finger: it holds an input action down while it's held.

PropertyTypeDefault
actionaction"jump"The action that it holds down while a finger is on it. With none, it only tells its script, with touched() and untouched().
playerint0The player whose action it presses: 2 for player 2. 0 uses the player of the piece that it is inside, or player 1.
shapeenum"circle"circle is the largest circle that fits in its rectangle. rectangle is the whole rectangle.
texttext""Words or a letter on the button.
imageresource""An image on the button: an arrow, a sword.
showenum"touch"touch shows it on phones and tablets, and on any screen after a finger touches it. always shows it everywhere, and the mouse can press it. never keeps it invisible, but fingers can still press it.
colorcolor{1, 1, 1, 0.3}The color of the button. The color is stronger while a finger holds the button.
textColorcolor{1, 1, 1, 0.9}The color of its words.
fontresource""A font, or empty for the default font.
sizeint (px)20The font size.
cornerRadiusnumber (px)8Rounds the corners.
Method
isDown()Returns true while a finger holds it down.
Event (a function in its script)
function touched()The engine calls it when a finger presses the button (or slides onto it).
function untouched()The engine calls it when the finger lets go or slides off.
